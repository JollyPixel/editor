# Voxel-model network API

The browser entry point is `@jolly-pixel/asset.voxel-model/client`. Server protocol utilities are exported from `@jolly-pixel/asset.voxel-model/server`. Use `assetRoomName("voxelmodel", assetId)` to name the room.

## Editable document

`ModelDocument` owns a `ModelTreeReader` at `tree`. Its edit methods validate a command, apply accepted changes locally, and emit a `change` event with `origin: "local"`. A change carries its `image`: `before`, the entries it replaced as they were before it, grouped like a snapshot as `{ nodes, materials, animationSets }` (`tree.imagesOf(command)`; for a node removal, `image.before.nodes` is the whole subtree it took), and `order`, the ids of every entry in tree order, grouped the same way. It also carries `inverse`, the commands that undo a local change, computed before it applies (empty for a remote change). An undo or redo change also carries `basis`, the room version of the step it replays, which the sync client sends with the command. The document is a `CommandDocument` from `@jolly-pixel/network/client`. `apply(command, clientId)` applies a remote command the tree accepts and emits a remote change naming its peer; it returns `false` and changes nothing when the tree refuses the command. `replayPending(command)` does the same with `origin: "replay"`, for the reconciler re-applying this client's pending commands after a peer's. `receipts` is a `ChangeReceipts` from `@jolly-pixel/network/client` that the sync client fills with the version each local change landed at, or its refusal. `applyStep(command, basis)` applies an undo or redo command as a local edit (a re-added or moved entry whose former next sibling is gone lands last). `modelHistoryKeys(tree)` returns the keys a `CommandHistory` registration needs: the conflict keys plus `subtree:<id>` and `material-subtree:<id>`, written by any change inside the entry and guarded by undoing the entry's creation. `load(snapshot)` replaces the tree and emits `reset`; a snapshot with a repeated node or material id, a missing parent or material, or a cycle throws `InvalidModelTreeError` (with its `entry`, `"node"` or `"material"`, and `id`) and leaves the tree as it was.

- `addBlock({ name, parentId?, id?, beforeId?, transform?, uv?, materialId? })` and `addFolder({ name, parentId?, id?, beforeId? })` return the new ID, or `null` when rejected. The node lands before the sibling `beforeId`, or last among its siblings without one.
- `remove(id)`, `rename(id, name)`, `move(id, parentId, { transforms?, beforeId? }?)`, `transform(id, transform, flipAxes?)`, `setUv(id, uv)`, and `assignMaterial(id, materialId | null)` return a boolean. A move carries its block transforms in the same command and places the node before the sibling `beforeId`, or last among its new siblings without one; `transform`, `setUv`, and `assignMaterial` target a block. A `flipAxes` with no axis set clears the block's flip.
- `addMaterial({ name, id?, parentId?, beforeId?, surface? })` and `addMaterialFolder({ name, id?, parentId?, beforeId? })` return the new ID, or `null` when rejected. `parentId` is a material folder, or the library root by default; the entry lands before the sibling `beforeId`, or last without one.
- `linkAnimationSet({ id, kind }, { own? })` links an animation set asset with no track remapped; `own: true` makes it the set holding this model's own clips, refused when the model already owns one. `shareAnimationSet(id)` turns the own set into a plain linked one. `unlinkAnimationSet(id)` removes the link, `remapAnimationTrack(id, path, target)` remaps one track of a linked set to another block path, or to `null` to ignore it, and `clearAnimationTrackRemap(id, path)` drops that remap so the track binds by its own path again. Each returns a boolean.
- `moveMaterial(id, parentId, beforeId?)`, `removeMaterial(id, { keepContents? })`, `renameMaterial(id, name)`, and `changeMaterial(id, surface)` return a boolean. The first three take a material or a folder; removing a folder removes everything in it, and removing a material leaves its blocks without one. `keepContents` removes a folder alone and moves its entries up to its place, in their order, in one command. `changeMaterial` takes a `MaterialSurfacePatchJSON` and keeps the fields it does not name.

A model owns a material library: `ModelMaterialJSON` `{ kind: "material", id, parentId, name, surface }` entries sorted into `MaterialFolderJSON` `{ kind: "folder", id, parentId, name }` entries, both `MaterialEntryJSON`. An entry's `parentId` is a folder or `null` for the root. A block points to a material, never a folder, with its optional `materialId`. A `MaterialSurfaceJSON` has `color` and `emissive` as lowercase `#rrggbb`, `opacity`, `roughness`, and `metalness` from 0 to 1, and `emissiveIntensity` from 0. A block without a material renders as `createMaterialSurface()`, and `createMaterialSurface(overrides?)` fills the fields it is not given from that default. `materialSurfaceChanges(current, next)` returns the fields of `next` that differ, as a patch that is empty when none do, and `holdsSurfacePatch(surface, patch)` tells whether a surface already has every field of a patch. `MATERIAL_SURFACE_KEYS` lists the surface fields and `MATERIAL_SURFACE_PROPERTIES` holds the JSON schema of each; the network schemas are built from them. `isMaterialSurface(value)` checks a value against those rules without the schema compiler, so browser code can validate input, and `isMaterialSurfacePatch(value)` does the same for a patch.

`encodeMaterialTransfer(materials)` writes materials as clipboard text tagged with `MATERIAL_TRANSFER_KIND`, as `MaterialTransferJSON` `{ name, surface }` without their ID or place in the library; `decodeMaterialTransfer(text)` returns them, or `null` for any other text or an invalid material.

A block's required `uv` is its `UVLayoutData` from `@jolly-pixel/asset.pixel-art`: a UV region without its identity. The model owns it; the texture only stores pixels. `addBlock` defaults it to `createBlockUv()`, the six faces unfolded as a net at the texture origin. `createBlockUv(origin)` places that net elsewhere, and `nextBlockUvOrigin(layouts, textureSize)` returns the first cell, row by row, where a net overlaps none of `layouts`, or the texture origin once the texture is full. `blockUvBounds(layout)` is the rectangle a layout covers, and `blockUvExtent(layouts)` the smallest texture size that holds them all.

`ModelTreeReader` exposes `size`, `has`, `get`, `block`, `materialIdOf`, `values`, `blocks`, `childrenOf`, `nextSiblingOf`, `subtreeOf`, `imagesOf`, `enclosingBlockOf`, `transformParentOf`, `placeable`, `materials`, `animationSets`, `blocksUsing`, `materialUses`, and `accepts`. Block names should be unique among the blocks sharing a block parent (`transformParentOf`, folders skipped), compared trimmed and case-insensitively. The tree still accepts clashes; `blockNameTaken(tree, name, parentId, exceptId?)` tells whether a block placed under `parentId` would clash, `freeBlockName(tree, name, parentId)` returns `name` or the first free `name 2`, `name 3`..., and `blockNameClashes(tree)` the IDs of every block sharing its name with a sibling block. `placeable(command)` returns the command without a `beforeId` the tree would refuse, so it lands last instead. `nextSiblingOf(id)` is the ID of the node right after `id` under the same parent, or `undefined`. `materialIdOf(id)` is a block's `materialId` without copying the block, and `blocksUsing(materialId)` the IDs of the blocks pointing to a material. `materials` reads the library in its order: `size`, `has`, `get`, `values`, `childrenOf`, `nextSiblingOf`, and `subtreeOf` cover materials and folders, and `material(id)` and `materials()` only materials. Names are labels and may repeat; entries are told apart by ID. `materialUses()` maps every material ID to the number of blocks using it, reads return copies. `ModelTree` itself also loads a whole snapshot with `load(snapshot)` and returns one from `toJSON()`. `createBlockTransform(overrides?)` creates the identity transform of a unit block.

## Animation sets

A model plays animation set assets from `@jolly-pixel/asset.voxel-animation` through its links, `tree.animationSets` (`size`, `has`, `get`, `values`, `owned`). A link names the set and the bindings this model overrides; `owned` is the link marked `own`, the one set holding the model's own clips, if any; every linked set is one of the model's dependencies, so the catalog knows which models use a set. A document written before links existed loads with none.

A set's tracks target block paths. `blockPathOf(tree, id)` is a block's path: the names of its block ancestors and its own, joined by `/`, folders left out, so moving blocks between folders keeps their paths. A name holding `/` cannot be told apart from a path. `blockPaths(tree)` maps every path, by its `trackPathKey` from `@jolly-pixel/asset.voxel-animation` (each name trimmed, any case, as sets compare track paths), to the blocks on it; remaps match paths the same way. `bindTracks(paths, link, tree)` maps each path, in order, to `{ state, blockId, remap }`: a remap replaces a track's path by its target (`null` ignores the track: `ignored`), then the path is `bound` when exactly one block has it (`blockId` is that block), `ambiguous` when several sibling blocks share a name on it, and `missing` when none does; `remap` is the link's remap of the track, or `null`. `boundBlocks(binding)` keeps the bound tracks as a path-to-block map. A remap targets a path rather than a block id, so it reconnects to a block deleted and made again under the same name.

`poseBlock(rest, sample)` poses a block's rest transform with an `AnimationSample`: position adds to it, rotation adds per axis in degrees, scale multiplies it, and a channel the sample lacks keeps its rest value. `poseDelta(rest, pose)` is its inverse: the full sample (every channel) that poses `rest` into `pose`; a scale axis resting at 0 keeps a factor of 1. `trackPathOf(link, tree, id, paths?)` is the track that drives a block: one of `paths` (a clip's tracks) bound to it, else the track a remap of the link points at the block's path, else `blockPathOf`.

## Undo

Undo goes through a [`CommandHistory`](../../../network/docs/sync/CommandHistory.md) with the document registered under `modelHistoryKeys(document.tree)`. A step undoes as the commands its changes' `inverse` holds, sent with the step's `basis`. It is refused as soon as a peer writes a value it guards (the values its undo would write back, per conflict key, plus the subtree of an entry whose creation it undoes), or as soon as a reload leaves one of them different; a peer editing another value of the same entry leaves it undoable.

## Synchronization

`new DocumentSyncClient(room, { document, keys: voxelModelWriteKeys })`, with `DocumentSyncClient` from `@jolly-pixel/network/client`, sends local document changes and applies peer commands and snapshots. Local changes stay pending until the server acknowledges them. The client keeps each change's image: a peer command reverts the pending changes with one `load` that puts back what they replaced, in the order the oldest one found, applies, and replays them. A pending change the tree now refuses, such as a move into a removed folder, leaves the tree until the server repairs it. Construct it before `room.join()`. `destroy()` removes document and room listeners; the caller leaves the room and owns the shared network client.

`new SyncedModelDocument(room)` creates the document and a private sync client. `ready` resolves after the first snapshot and `loaded` reports it; `dispose()` destroys the sync client. `voxelModelDocumentKind()` exposes the same construction through a `@jolly-pixel/editor.host` document-kind adapter. The sync client inherits `snapshot`, `ready`, `command`, and `notice` events; notices report rejected edits or asset deletion.

## Wire commands

The snapshot is `{ nodes: ModelNodeJSON[], materials: MaterialEntryJSON[], animationSets: AnimationSetLinkJSON[] }`, siblings in array order; a load rejects a block whose `materialId` names no material and a library entry whose parent is not a folder. `VoxelModelNetworkCommand` adds `clientId`, `seq`, and `timestamp` to one of these commands:

- `node-added` carries a full folder or block node and an optional `beforeId` that must be a sibling under the node's parent. `node-removed` carries an ID and removes its subtree; `node-renamed` carries an ID and name.
- `node-moved` carries an ID, new parent ID, block transforms changed by the move, and an optional `beforeId` that must be a sibling under the new parent. Sibling order is the node order of the snapshot.
- `node-transformed` carries a block ID, transform, and optional flip axes.
- `node-uv-changed` carries a block ID and its whole UV layout.
- `node-material-changed` carries a block ID and a material ID of the model, or `null` to clear it.
- `material-added` and `material-folder-added` carry a full entry with an unused ID under the root or a folder, and an optional sibling `beforeId`. `material-moved` carries an ID, a new parent folder or `null`, and an optional sibling `beforeId`; a folder cannot move into its own subtree.
- `material-removed` carries a material or folder ID, removes its subtree and clears the removed materials from every block using them; with `keepContents: true` it takes only a folder, which goes alone while its entries take its place; `material-renamed` carries an ID and name; `material-changed` carries a material ID and a surface patch of one or more fields, merged into the stored surface.
- `animation-set-linked` carries an `AnimationSetLinkJSON` `{ id, kind, bindings, own? }` for a set not linked yet; every binding `{ path, target }` remaps a track to a block path or `null`, one per path, and `own: true` is refused when another link has it. `animation-set-unlinked` carries a linked set ID. `animation-set-owned` carries a linked set ID and `own`; making a set owned is refused while another one is (the conflict key is `animation-own:<set id>`). `animation-binding-changed` carries a linked set ID, a track path and a `target`: a block path, or `null` to ignore the track on this model. `animation-binding-cleared` carries a linked set ID and a track path, and drops its remap so the track binds by its own path again. Both compare paths with `trackPathKey`, and their conflict key is `animation-binding:<set id>:<path key>`.

`voxelModelCommandProtocol` validates commands and `voxelModelSnapshotSchema` validates snapshots. `VoxelModelCommandArbiter.admit(state, command)` returns an admission, or `null` when `state.accepts(command)` is false or a key rejects it; `voxelModelConflictKeys(command)` returns the collision keys described in [architecture](../ARCHITECTURE.md), and `voxelModelWriteKeys(command)` the registers a rename, transform, UV change, material assignment or material rename or surface change sets for the client reconciler. The stored document also has a version and a required texture reference; these are outside the live snapshot.
